ResearchAgent

A research agent with a wallet.

It answers from free sources first. When the missing piece sits behind a paywall, it can buy that one article straight from the writer, for cents, inside a budget you set. If the article doesn't contain what the writer promised, the money comes back.

The whole system

Who does what

An LLM writes. A decision model judges what's worth buying. Plain code pays. The writers' sites and their search run on this laptop, so nothing comes from the open web. The models and the ledger are real online services.

Online: DeepSeek (writes), OpenAI Decisions · gpt-6-luna (judges; Cloudflare's Clef-flash is the one-line fallback), Cloudflare Workers AI (turns text into numbers for search), XRPL Testnet (settles payments). On this laptop: the engine, the wallet's spending rules, and eight writers' sites. The writers and their 81 articles are fictional and labelled SYNTHETIC.

Step 1 · Search

Every writer searches its own shelf.

There is no central index. The question goes to each writer's site. Each one searches its own articles and sends back a teaser and a signed list of promises. The paid text stays on the writer's server until someone pays.

Real numbers from the run: 16 hits from 8 writers in 0.75 s, hybrid mode. Hybrid means two searches mixed: matching words, and matching meaning. If the meaning search is down, the screen says "keyword only".

Under the hood
  • Each writer's site runs Orama hybrid search (BM25 keywords + vectors) over its own full text, in its own process.
  • Cloudflare Workers AI (bge-base-en-v1.5) turns text into 768 numbers. Articles are embedded once when the corpus is built; the question is embedded live. Close numbers mean close meaning.
  • The engine merges every writer's list with reciprocal-rank fusion. Price is not an input to ranking, and rewrites collapse into their source's family.

Step 3 · Decide

A decision model scores what's worth buying.

It reads each paywalled article's public teaser and returns numbers, not prose: does it fill the gap, is it original, is it credible. Code multiplies those by the writer's track record and compares value per dollar.

Step 4 · Only code pays

The budget is the only permission to spend.

The LLM has no buy button. It can say what's missing. It can't pick a purchase, raise the budget or pay. That happens in a few lines of ordinary code.

server/agents/decision.ts · the whole spending decision
// trust can only lower value, never the budget or cap
if (status !== 'active') verdict = 'SKIP_LOW_TRUST'
else if (rewrite)        verdict = 'SKIP_REWRITE'
else if (price > cap)    verdict = 'SKIP_OVER_CAP'  // S$1
else if (value < 0.20)   verdict = 'SKIP_LOW_VALUE'
else if (price > left)   verdict = 'SKIP_OVER_BUDGET'
else                     verdict = 'BUY'

// best value per dollar wins
pick = rows.filter(BUY).sort(byValuePerDollar)[0]

  • The LLM gets tools that can't spend: ask you a question, propose a plan, write the report.
  • S$1 cap per article, at most 3 buying rounds, buy only above the 0.20 bar.
  • One charge per intent. The signed payment is saved before it is sent, so a retry resends the same transaction and can't pay twice.

Step 5 · Pay over HTTP

Paying is one extra round trip.

HTTP has had a status code for this since 1997: 402 Payment Required. x402 puts the price in a header. The agent pays on the ledger and asks again with the signed payment attached. Like a vending machine that speaks HTTP.

Step 6 · Verify

Neither side trusts the other.

The writer checks the payment on the ledger before it delivers. The agent checks the writer's signature before it pays, then recomputes every promise after delivery.

ANALOGYThe manifest is a sealed envelope with fingerprints on the outside. Before paying you can't read the passages, but you can see their fingerprints (salted hashes). After paying you get the salts, so you can recompute every fingerprint and check every promise. A promise names the kind of fact, never its value, so it gives nothing away.

Real passages from the two articles bought in the run. AlphaLeak's fingerprints all matched (the text is what it said it was) but its promised dated figure isn't in the text. Fingerprint = sha256(salt ‖ index ‖ passageId ‖ text); the manifest is signed by the same XRPL key that receives the payment.

Step 7 · Refund and track record

A broken promise costs the writer.

The agent challenges the writer. The writer's own server re-checks and refunds on the ledger. Its track record drops either way, so a cheat gets one sale and then gets blocked.

track record = (kept + 4) ÷ (kept + 5 × broken + 5)  ·  new writer: 4 ÷ 5 = 0.80  ·  one broken: 4 ÷ 10 = 0.40  ·  one kept: 5 ÷ 6 = 0.83

The answer changes

Answer v2: Kestrel's Penang lead time fell from 26 weeks (1 Jun) to 22 (1 Aug) to 18 (15 Sep 2026), a cut of 31% while capacity grew from 11,000 to 16,000 units a month. 2 of 2 requested facts answered.

The ledger can't force a refund: it can check a hash and a deadline, not whether a sentence contains a date. So the penalty lives in the track record. A writer who refuses or ignores a challenge for 30 s loses twice as much and is delisted. Calibration also counts: AlphaLeak claimed relevance 0.96 and delivered 0, so its score is multiplied by 1 − 0.96² = 0.08 as well.
