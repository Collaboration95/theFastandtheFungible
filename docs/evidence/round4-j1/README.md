## Reproduction and evidence limits

Build the portable MCP runtime with the release packager, retain its tgz outside the frontend build output, then run:

```sh
RA_ACCEPT_TESTNET=1 node --import tsx scripts/judge-bank-testnet.ts /absolute/path/researchagent-mcp.tgz
```

The harness unpacks the tgz and launches its stdio executable with only operator caps and private faucet state. `wallet_status` must report xrpl-testnet. Purchases go through `ask_expert`; independent SDK receipt verification checks Testnet ledger transactions. Terminal snapshots are checked by gate-audit. Ordinary unit and replay tests additionally check pre-grant publication boundaries. This measurement does not sample every bank run SSE frame.

A simultaneous UI build removed dist/release after question 19 completed. The harness resumed the same unpacked runtime and private durable state with the same idempotency keys; question 19 was recovered without a new purchase, then question 20 ran. Completed gate-audit records were normalized from their original report envelope into violation arrays. The recorded original tgz SHA-256 is `07a08c4c0ff4988708267ee813b888e6ab560997744f921f6136b90efbabf8fe`. The original tgz was local acceptance input, not a published release asset.

To resume an interrupted run, preserve its original private state and results file and set `J1_RESUME=1 J1_STATE_DIR=<original-private-state-dir>`. No private wallet state is committed.
